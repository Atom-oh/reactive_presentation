붙인 뒤의 일: 수명 주기, 단절, 버스팅

노드 수명 주기: 업그레이드는 교체가 기본

조인
의존성 설치kubelet, containerd
→
자격 증명 설정, EKS 조인nodeadm이 조인
→
CNI 설치그 전 NotReady는 정상
→
Ready 검증워크로드까지 확인
업그레이드 순서
뒤처진 노드 정리컨트롤 플레인 마이너로
→
컨트롤 플레인다음 마이너로 먼저
→
노드 교체새 호스트 검증 후 교체
→
Cilium한 마이너씩
버전 skew: kubelet은 API 서버보다 새로울 수 없고, 최대 3개 마이너까지 뒤처질 수 있습니다. 허용 범위일 뿐 유지하라는 권장은 아닙니다.
롤백 명령은 없음
실패한 노드는 cordon을 유지하고, 승인된 버전의 호스트로 교체합니다.
릴리스 노트는 직접 점검
EKS 최적화 AMI가 아니라 고객 OS 이미지라서 "AMI는 영향 없음" 문구가 해당되지 않습니다.
Bottlerocket은 별도 경로
nodeadm 대신 자체 설정 경로로 조인, 업그레이드, 제거합니다.

연결이 끊기면: 300초와 1시간

단절되면
Lease 갱신이 끊기고 잠시 뒤 노드는 Unknown, unreachable taint가 붙습니다.
실행 중인 Pod는 바로 옮겨지지 않습니다.
300초 뒤
toleration이 없는 Pod는 기본값으로 eviction됩니다.
DaemonSet은 이 taint를 기본으로 견딥니다.
1시간 넘게
SSM 자격 증명은 1시간 고정이라 만료됩니다.
IAM Roles Anywhere는 기본 1시간, 최대 12시간
연결 복구
SSM은 재시도 간격 때문에 재연결이 최대 30분 늦을 수 있습니다.
IAM Roles Anywhere는 보통 몇 초
1. 연결을 전제로 설계
간헐 연결, 단절 환경용이 아닙니다. 안정적인 사설 양방향 연결을 유지합니다.
2. 옮기기 어려운 앱은 tolerationSeconds
늘리면 짧은 단절은 견디지만, 실제 장애 노드의 Pod 이전도 늦어집니다.
3. 복구 속도로 자격 증명 선택
빠른 복구나 긴 세션이 필요하면 IAM Roles Anywhere. SSM이면 복구 후 agent 재시작 절차를 준비합니다.

버스팅: 온프렘 먼저, 넘치면 클라우드

온프렘 우선hybrid 노드를 선호하도록 배치
→
자리가 없으면 Pending스케줄되지 못한 Pod
→
Karpenter가 EC2 생성burst 노드에 스케줄
→
줄일 때 온프렘 보호pod-deletion-cost로 클라우드 Pod를 먼저
Pending Pod에 반응
온프렘 포화를 감지하는 기능이 아닙니다. 조건과 toleration이 맞는 Pending Pod에 반응합니다.
deletion cost는 선호
ReplicaSet 축소 때의 best-effort 순서입니다. NotReady인 온프렘 Pod는 먼저 지워질 수 있습니다.
자동 복귀 없음
온프렘 용량이 돌아와도 실행 중인 클라우드 Pod는 돌아오지 않습니다.
정책 없음, Kyverno, Kyverno + Karpenter: 세 방식으로 줄였을 때 어느 Pod가 남는지는 오늘 5부 영상에서 직접 봅니다.
