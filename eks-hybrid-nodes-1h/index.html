사전 준비
PKI 불필요, activation 코드Activation 코드와 ID만 있으면 등록합니다. 활성화는 기본 24시간, 최대 30일 유효하고 하나로 1~1000대까지 등록합니다. 코드가 노출되면 그 기간에 누구나 등록할 수 있으니 짧게 만들고 노드별로 전달하세요.
CA와 노드별 인증서trust anchor(CA), profile, role, 노드별 인증서와 개인 키가 필요합니다. 사내 PKI가 있으면 재사용하고, 없으면 AWS Private CA를 쓸 수 있지만 그 요금은 별도입니다.
단절 후 복구
최대 30분 지연 가능끊기면 SSM agent가 간격을 늘려 가며 재시도하고, 그 간격이 최대 30분입니다. 자격 증명이 만료되면 네트워크가 돌아와도 갱신될 때까지 재연결되지 않고, 노드마다 시점이 다릅니다. agent를 재시작하면 바로 갱신합니다.
보통 몇 초kubelet이 필요할 때마다 자격 증명을 받기 때문에, 네트워크가 돌아오면 보통 몇 초 안에 재연결됩니다.
세션 길이
1시간 고정바꿀 수 없습니다. 만료 전에 자동으로 교체되고, 평소에는 노드와 애플리케이션에 영향이 없습니다.
기본 1시간, 최대 12시간profile 설정으로 늘릴 수 있고, 노드 IAM role의 최대 세션 길이도 함께 맞춰야 합니다. 길게 잡으면 짧은 단절은 견디지만 유출 시 노출 시간도 길어집니다.
노드 이름
mi-* ID로 자동SSM이 만든 managed instance ID가 노드 이름이 됩니다. 사람이 읽기 어려우니 위치와 역할은 label로 붙이세요.
인증서 CN과 연결노드 이름은 인증서 CN과 맞춰야 합니다. 설정 방법은 Deep Dive 3부에 있습니다.
운영 부담
activation과 agent 관리활성화 만료와 등록 한도, SSM agent 버전, 노드 제거 시 등록 해제를 관리합니다. 등록 자체는 무료지만 hybrid 노드에 Session Manager나 Run Command를 쓰면 2026-09-30부터 사용량 과금입니다.
인증서 발급, 갱신, 폐기노드별 인증서 배포, 만료 전 갱신, 폐기를 운영해야 합니다. 인증서가 만료되면 자격 증명을 받을 수 없으니 만료 알림을 켜 두세요. IAM Roles Anywhere 자체는 추가 요금이 없습니다.
필요한 연결
SSM 리전 엔드포인트갱신하려면 SSM 엔드포인트에 닿아야 합니다. 사설 연결만 쓰면 interface VPC endpoint(PrivateLink)를 준비합니다.
Roles Anywhere 엔드포인트갱신하려면 IAM Roles Anywhere 엔드포인트에 닿아야 합니다. 로컬 CA가 있어도 AWS 없이 자격 증명을 발급받을 수는 없습니다.
SSM이 맞는 경우
사내 PKI가 없고 빨리 시작해야 할 때, 연결이 안정적이어서 단절 후 복구 지연을 감수할 수 있을 때.
IAM RA가 맞는 경우
PKI와 인증서 수명 관리 체계가 이미 있을 때, 단절 후 빠른 복구나 긴 세션이 필요할 때.
공통
한 클러스터에서는 한 방식만 쓰는 것이 권장입니다. 두 방식 모두 갱신에 AWS 연결이 필요합니다.

어디서 들어오느냐로 경로가 갈린다

VPC에서 hybrid Pod로
Cloud Pod, 컨트롤 플레인, ALB → Gateway 또는 BGP, static route → 온프렘 Pod
ALB IP 타깃 등록과 해제는 AWS Load Balancer Controller(LBC)가 하고, Gateway나 라우팅은 Pod IP까지 가는 경로만 줍니다.
온프렘에서 리전 Pod로
온프렘 → DX, VPN → internal ALB → 리전 Pod
일반 VPC 경로라 Gateway가 관여하지 않습니다. 온프렘 DNS가 ALB 이름을 private IP로 풀어야 합니다.
온프렘에서 hybrid Pod로: hairpin
온프렘 → ALB → Gateway → 다시 온프렘
동작은 하지만 DX를 두 번 지나 지연과 전송 비용이 늘어납니다.
AWS 권장: 리전에서 오는 트래픽은 ALB, 온프렘에서 오는 트래픽은 온프렘 쪽 Ingress나 LB로 받습니다. Gateway를 쓰면 Cilium L7 기능이 꺼지므로 온프렘은 L4 LoadBalancer나 기존 LB를 씁니다.

IAM Roles Anywhere는 보통 몇 초
1. 연결을 전제로 설계
간헐 연결, 단절 환경용이 아닙니다. 안정적인 사설 양방향 연결을 유지합니다.
2. 옮기기 어려운 앱은 tolerationSeconds
늘리면 짧은 단절은 견디지만, 실제 장애 노드의 Pod 이전도 늦어집니다.
3. 복구 속도로 자격 증명 선택
빠른 복구나 긴 세션이 필요하면 IAM Roles Anywhere. SSM이면 복구 후 agent 재시작 절차를 준비합니다.

버스팅: 온프렘 먼저, 넘치면 클라우드

온프렘 우선hybrid 노드를 선호하도록 배치
→
자리가 없으면 Pending스케줄되지 못한 Pod
→
Karpenter가 EC2 생성burst 노드에 스케줄
→
줄일 때 온프렘 보호pod-deletion-cost로 클라우드 Pod를 먼저
Pending Pod에 반응
온프렘 포화를 감지하는 기능이 아닙니다. 조건과 toleration이 맞는 Pending Pod에 반응합니다.
deletion cost는 선호
ReplicaSet 축소 때의 best-effort 순서입니다. NotReady인 온프렘 Pod는 먼저 지워질 수 있습니다.
자동 복귀 없음
온프렘 용량이 돌아와도 실행 중인 클라우드 Pod는 돌아오지 않습니다.
정책 없음, Kyverno, Kyverno + Karpenter: 세 방식으로 줄였을 때 어느 Pod가 남는지는 오늘 5부 영상에서 직접 봅니다.

6부: 도입 전에 정할 여섯 가지

1. 연결

안정적인 사설 양방향 연결이 있는가
DX 또는 VPN, 양방향 route. 간헐 연결, 단절 환경용이 아님
3부, 4부

2. CIDR

네 가지 CIDR이 서로 겹치지 않는가
VPC, Service, remote node, remote Pod. 나중에 바꾸기 어려움
3부

3. 라우팅 방식

BGP, static, Gateway 중 무엇인가
라우터 팀이 BGP를 운영할 수 있으면 BGP. 어려우면 Gateway, 대신 Cilium L7 끔, leader AZ 비용
3부, V1, V3

4. 자격 증명

SSM인가, IAM Roles Anywhere인가
단절 후 복구 속도와 인증서 운영 역량으로 고름
2부, 4부

5. CNI

클라우드 노드가 있는가
hybrid는 Cilium. 클라우드 노드가 있으면 VPC CNI와 혼합, webhook은 클라우드에
3부

6. 운영

교체, 단절, 버스팅을 준비했는가
골든 이미지와 여유 용량, 300초 eviction 대비, Pending 기반 버스팅과 축소 정책
4부, V2
