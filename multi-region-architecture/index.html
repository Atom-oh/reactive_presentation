Active-Active냐, Passive냐

Active-Active
  • 모든 리전이 동시에 트래픽 처리, 사용자는 가까운 리전으로
  • 리전 하나를 잃어도 다른 리전이 이미 서비스 중
  • 쓰기를 양쪽에서 받으면 충돌 해결 또는 동기 합의가 필요
  • 각 리전이 전체 부하를 흡수할 용량을 유지해야 함
Active-Passive
  • Primary만 트래픽 처리, secondary는 대기 또는 축소 운영
  • DR 전략 스펙트럼: Backup & Restore, Pilot Light, Warm Standby
  • 단방향 복제라 충돌이 없고 구현이 단순
  • 페일오버 절차와 승격 시간이 RTO를 결정
이 세션의 선택: 읽기는 Active-Active, 쓰기는 Active-Passive. 두 리전 모두 트래픽을 받되 쓰기는 us-east-1 한 곳으로 모읍니다 (Write-Primary / Read-Local).

DocumentDB 장애는 failover로

정상 상태의 global cluster에서 primary 리전을 옮깁니다. 훈련, 리전 순환, failover 후 원복에 씁니다.

aws docdb switchover-global-cluster \ --region us-east-1 \ --global-cluster-identifier mall-catalog-global \ --target-db-cluster-identifier arn:aws:rds:us-west-2:<ACCOUNT>:cluster:catalog-usw2

모든 secondary가 동기화될 때까지 기다린 뒤 전환하므로 데이터 손실이 없습니다. 모든 리전의 engine version이 같아야 하고, 역할 전환은 수 분까지 걸릴 수 있습니다.

primary 리전 장애 시 secondary를 승격합니다. 명령은 승격할 리전에서 실행합니다.

aws docdb failover-global-cluster \ --region us-west-2 \ --global-cluster-identifier mall-catalog-global \ --target-db-cluster-identifier arn:aws:rds:us-west-2:<ACCOUNT>:cluster:catalog-usw2 \ --allow-data-loss

실행 전 GlobalClusterReplicationLag(ms)가 가장 작은 secondary를 고릅니다. 보통 1분 안에 승격되며 복제되지 않은 쓰기는 유실될 수 있습니다. 이전 primary는 회복 후 자동으로 secondary로 재합류합니다.

Key Takeaways

1. 기본은 단일 writer
지금은 전부 단일 writer Warm Standby. RPO 0이 필수인 테이블만 DSQL Active/Active를 검토합니다.
2. 가장 약한 고리가 RTO, RPO
MSK Replicator가 없으면 DB가 넘어가도 이벤트는 남습니다. Aurora failover는 lag만큼 잃고 rds.global_db_rpo로 상한을 둡니다.
3. 엣지는 읽기만 자동
CloudFront origin failover는 GET, HEAD, OPTIONS만. 쓰기는 KVS의 활성 리전 값으로 전환합니다.
4. 전환은 plan으로
Region switch는 활성화 리전에서 실행됩니다. 기본 block이 없는 단계는 멱등 Lambda로 채웁니다.
5. 명령을 구분
Aurora, DocumentDB 장애는 쓰기 중지 후 failover + allow-data-loss, 계획 전환과 원복은 switchover. ElastiCache는 수동 promote.
6. 숫자는 훈련으로
FIS 시나리오와 Region switch 리허설로 실측한 RTO/RPO만 목표표에 씁니다.

OAM은 리전을 넘지 않는다

Cross-account observability (OAM)
  • sink와 link는 같은 Region에서만 연결
  • 계정당 Region별 sink 1개
  • monitoring 계정당 source 최대 100,000
  • metrics, logs, traces를 복제 없이 조회
Centralization rules
  • Organizations 기반, source Region 여러 개 선택
  • destination Region + backup Region
  • @aws.account, @aws.region 필드 보존
  • 첫 사본 무료, 추가 사본 $0.05/GB
Cross-account cross-Region 대시보드
  • metrics와 alarm 위젯용
  • logs와 traces는 지원하지 않음
  • alarm은 telemetry가 있는 Region에 생성
