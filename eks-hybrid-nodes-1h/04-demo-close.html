온프렘은 시뮬레이션: EC2 호스트와 TGW

클라우드 VPC 10.0.0.0/16

  • EKS 1.36, system 노드
  • Gateway 노드 2대 (2개 AZ)
  • Karpenter burst 노드 (m6i, m7i)
  • 클라우드 노드는 VPC CNI
Transit Gateway

시뮬레이션 온프렘 VPC 172.18.0.0/16

  • hybrid 노드 호스트 2대 (EC2, 각 4 vCPU)
  • GPU 호스트 1대 (g6.xlarge, V4 때만)
  • Pod CIDR 172.17.0.0/16 (Cilium)
  • 실제 구성에서는 DX 또는 VPN 자리
프로덕션 지원 구성이 아님
EC2를 hybrid 노드로 쓰는 것은 지원되지 않습니다. 동작 확인과 수치 확보가 목적입니다.
수치는 이 환경의 값
회차가 적은 측정입니다. 실제 온프렘 서버와 회선에서는 다시 재야 합니다.
보안 기준은 유지
인터넷 개방 ingress 없음, 공인 IP 없음, LB는 internal만

6부: 도입 전에 정할 여섯 가지

1. 연결

안정적인 사설 양방향 연결이 있는가
DX 또는 VPN, 양방향 route. 간헐 연결, 단절 환경용이 아님
3부, 4부

2. CIDR

네 가지 CIDR이 서로 겹치지 않는가
VPC, Service, remote node, remote Pod. 나중에 바꾸기 어려움
3부

3. 라우팅 방식

BGP, static, Gateway 중 무엇인가
라우터 팀이 BGP를 운영할 수 있으면 BGP. 어려우면 Gateway, 대신 Cilium L7 끔, leader AZ 비용
3부, V1, V3

4. 자격 증명

SSM인가, IAM Roles Anywhere인가
단절 후 복구 속도와 인증서 운영 역량으로 고름
2부, 4부

5. CNI

클라우드 노드가 있는가
hybrid는 Cilium. 클라우드 노드가 있으면 VPC CNI와 혼합, webhook은 클라우드에
3부

6. 운영

교체, 단절, 버스팅을 준비했는가
골든 이미지와 여유 용량, 300초 eviction 대비, Pending 기반 버스팅과 축소 정책
4부, V2
